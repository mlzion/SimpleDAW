Living experimental-branch decision log. Entries are approved design requirements unless otherwise marked; implementation requires separate phase authorization. CUI0/CUI1 is accepted. ## W01 — Piano Roll automatic vertical scrolling
Status: Windows live PASS; retain regression coverage.
Observation: opening Piano Roll by double-clicking a MIDI clip can obscure the clip being edited.
Requirement: after editor layout, automatically scroll synchronized Track List and Timeline vertically as far as necessary to keep the edited clip visible above Piano Roll. Preserve horizontal navigation, selection and existing highlighting. Test clips near bottom, different track heights and already-visible clips. Consider other docked editors separately.

## W02 — Master Drum Track positioning
Status: Windows live PASS; retain regression coverage.
Requirement: Master Drum Track remains above ordinary Track #1, cannot be reordered among ordinary tracks, and participates in normal vertical scrolling so it can scroll entirely out of view. Child lanes remain attached to parent. Verify existing behavior before changing code; preserve lane reorder within parent and existing numbering rules.

## W03 — Direct manipulation of timeline edit cursor and time window
Status: Windows live accepted for v0.26.2 with the G05 exception. F07 — Timeline ruler interaction isolation — is deferred to v0.26.3 for correction during Interaction Standardization.
- Edit cursor: click ruler to position as before; drag cursor icon horizontally following timeline snap; double-click icon returns to time zero. No selection step or UAT/CUI command targeting.
- Time window: drag ruler to create with continuous pointer-following visual preview between snap thresholds. Final range rounds drag distance from snapped start to nearest division, ties away from start, in either direction and at every successive threshold, including shrinking. Below first halfway threshold or returning to start and releasing leaves no window, even if a previous window existed. Never commit an unsnapped fallback range.
- Drag center icon to move entire window following snap, preserving duration. Double-click center icon deletes window. Provide vertical boundary handles aligned with center icon; drag either to resize only that boundary following nearest-division snap. Reaching the opposite boundary deletes the window.
- Remove cursor/window as UAT and CUI command targets; retain independent clip selection, existing loop semantics, timeline bounds, transport restrictions, ruler height and generous hit areas. Preserve time-window-dependent clip operations. Playback cursor is not a target. Snap OFF uses 10 ms. Changing snap does not resize existing window.
- F05 failed live at efa4ed2: lost continuous preview and previous range restored after zero-length drag. The revised implementation restores continuous feedback and clears zero-length drags. F06 review confirmed and removed ruler command precedence over retained clip selection. No additional command regression was reproduced in Linux verification. F01–F04 passed focused retests at e1f9ed9; F04 interaction superseded by redesign.

## W04 — Timeline snap increments and startup default
Status: Windows live PASS, including corrected snap arrows; retain regression coverage.
Ensure Timeline snap options include 1 Bar and 1/2 (half note), alongside 1/4, 1/8, 1/16, 1/32 and OFF (10 ms). Verify existing options before adding duplicates. Set 1 Bar as the default on program startup. Preserve meter-aware bar length and existing editor-specific snap behavior unless separately approved. Use compact left/right snap arrows above Move buttons, with bidirectional rollover and persistent popup. Retain selector on Move; Size page superseded by W06.

## W05 — Track List visual cleanup
Status: Windows live PASS for v0.26.2.
Remove Input 1 and Input 2 display icons from Track List rows; retain input configuration and routing functionality in Inspector. Restore approved compact ordinary track title format: track number immediately followed by A (Audio) or M (MIDI), space, user-assigned name (example: 3A Guitar 1). Do not append redundant Audio/MIDI type labels. Derive identifier from current track order and type; update after insert/delete/reorder, without changing stored user name. Preserve Master Drum Track and child lane numbering exemptions and existing functional controls. Implementation authorized in CUI2.

## W06 — Global mouse interaction and direct editing (v0.26.3)
Status: implemented on the experimental branch; Windows CI passed at `f0fa21b`; owner live acceptance pending. [Live checklist](testing/v0.26.3-live-test.md) Supersedes future Size page references in W04 and earlier CUI plans.
- Wheel navigates, never adjusts values: vertical scrolling in Track List/Timeline (synchronized), Inspector, Piano Roll and Drum Pattern Editor. Right button + wheel starting in empty workspace scrolls horizontally in Timeline and both musical editors. Latch gesture ownership at press; objects passing under pointer cannot retarget it. Suppress selection toggle after drag or wheel gesture. Open CUI consumes wheel for page cycling; preserve dismissal and snap controls.
- Right-click on object toggles selection; right-click empty area does nothing. In musical editors right-button vertical drag on a selected note/hit adjusts velocity instead of toggling selection. Retain existing Piano Roll behavior as reference; audit existing bindings and report conflicts. Left drag adjusts sliders and velocity bars. No wheel velocity adjustment or new velocity popup.
- Left press on selected object preserves set for drag; click without drag selects individual; unselected object selects individually. Latch operation and targets throughout gesture. Direct center drag moves selected clips/notes/hits; selected clip/note interior edges resize corresponding edges of entire set. Unfocused objects must first be selected for sizing. Narrow objects retain movement only; zoom in for sizing. Drum hits cannot be sized. Preserve type/lane compatibility and existing source bounds, minimum lengths and transport restrictions.
- Group move/size uses common snapped displacement, not independent absolute snapping. Opposite resize edges stay fixed; stop entire group at first applicable limit. Continuous feedback, one undoable gesture, no partial mutations. Audio resizing trims/reveals source, not time stretching. Drum movement supports horizontal and vertical lane movement; preserve velocity and subdivisions. Occupied destination replaces existing hit following Piano Roll replacement semantics; compute from original selection atomically, Undo restores displaced events. Verify actual Piano Roll collision rules before reuse.
- Drum Pattern Editor follows existing Piano Roll Draw/Select behavior as closely as practical; add mode control, retain subdivision popup. Both editors retain bottom velocity panels, make bars visible for active events without requiring focus, prioritize selected bars when overlapping. Right-drag provides access to individual or group velocity even for simultaneous events. Group velocity changes by common delta, stops at first 1/127 limit, numeric value/range feedback and one Undo per drag.
- F07: cursor and time-window gestures exclusively in ruler/handles; clip area cannot reposition cursor or manipulate window. Ruler interactions preserve clip selection/effective focus. Preserve W03 loop and snap semantics.
- Remove Size group from permanent UAT and experimental CUI; retain reusable sizing functions. Retain Move and Edit, initial Move page and quick snap selector. Apply direct editing to Classic and Experimental modes alike.
- Future Automation Editor and melodic step sequencer inherit global interaction principles; not implemented now. Mixer horizontal strip navigation is a proposed future exception, not current scope. Live editing during playback is a dedicated phase after Mixer; preserve existing transport permissions now and keep permission checks separate from editing operations where practical.
