## Required corrections

### R1 — 24-track ceiling (C03)
- Diagnose why complete-track UAT paste stops at 20. Support exactly **24 total tracks**, including copies, with unique Copy suffixes, insertion below current selected track and full copied state.
- At 24 tracks disable/reject the next paste with no partial changes. Check any other track-creation pathways for consistent limit enforcement.
- Automated tests: copy/paste to 21–24, reject 25, undo/redo and save/reopen.

### R2 — Clip minimum duration (E03)
- SIZE must never reduce clip playback duration below **1/16 of a measure**; reject invalid shrink atomically and keep original source untouched. This is a duration rule, not merely an 8–10 pixel display minimum.
- Preserve Snap ON selected-grid increment and Snap OFF exact 10 ms per press; neither overrides the minimum duration. Use the meter at the clip’s start before the press and measure the result in musical beats across tempo changes. Keep existing shorter clips valid and allow extension by a full step. Preserve source boundaries.
- Automated tests for START+/END− near threshold, Snap ON/OFF, zero/source boundaries, undo/redo.

### R3 — Independent selections and focus/highlight consistency (F01–F02)
- Keep one stored selected Track List track and a separate multi-clip Timeline selection. Switching focus must not clear the other area's selection.
- Tracks focused: highlight the one stored selected track. Timeline focused: highlight **all and only** tracks containing currently selected clips. Clear the previous track's stale active highlight when it is not in that set; if Timeline has no selected clips, do not retain a misleading track highlight.
- Apply identical behavior to left-click, right-click toggle, empty-area box selection, clip operations and focus switches. Visual highlight is not actual track multi-selection; track UAT operations always target the single selected track when Tracks has focus.
- The Inspector is governed by the **focused area**, never stale highlight. Keep any existing Inspector behavior working, but do not implement full Inspector or add Inspector-dependent acceptance gates in this PR.
- Automated tests for switching focus both directions, selection preservation, multi-track clip membership, no stale highlights, UAT target isolation.

### R4 — Audio/MIDI track typing and compatibility (F03)
- Establish explicit Audio and MIDI track types with clear track header identification, persistence and appropriate creation/duplication behavior.
- For existing audio and MIDI clips, validate compatible destination track type on paste, MOVE UP/DOWN and drag. Reject incompatible operations, including entire multi-clip group, before mutation; no implicit conversion or new tracks.
- Retain compatible existing tracks and clips. Infer untyped homogeneous tracks from their clips. Detect prior MIDI creation labels for empty tracks and otherwise use Audio. Report unexpected mixed legacy tracks without changing their clips. Use an OK warning for incompatible placement and apply the same check to Audio File and MIDI Item insertion. Preserve existing working MIDI features.
- Automated tests: valid/invalid single and group moves/pastes, persistence, no partial mutations, undo/redo.
