# SimpleDAW v0.22.2 — First implementation task sheet
Status: **APPROVED DESIGN / NOT IMPLEMENTED / NOT TESTED** · 2026-11-20

## Goal
Combine the previously proposed v0.22.2 toolbar correction and v0.22.3 MOVE/SIZE work into **one v0.22.2 development build and Windows live acceptance cycle**. Make EDIT, MOVE and SIZE useful for existing Timeline clips and Tracks objects, without expanding into MODIFY, recording or new creation workflows.

## Governing interaction contract — ACCEPTED
1. Target resolution follows **Editing Windows > Inspector > Timeline > Tracks**, with the established active-area and fallback behavior.
2. The active area determines the object domain. Selected objects within that domain are the action targets. Preserve independent selections in other areas.
3. A group may contain **multiple objects of the same type** (clips *or* tracks). Never combine tracks and clips in one operation. Do not implicitly merge selections from separate areas.
4. Group operations are **atomic**, with one undoable transaction; validate all selected objects and destinations first. Reject the whole operation rather than partially applying it.
5. Fixed action labels/positions; unsupported actions visibly disabled. Keep the existing mouse-selection and focus rules. Do not require keyboard modifiers.
6. Preserve existing Tracktion Edit/UndoManager and central action dispatcher. Global Undo/Redo is independent of active area.

## Task B — Toolbar and EDIT
- EDIT fixed 2×2: **CUT | DELETE / COPY | PASTE**, replacing disabled CREATE.
- Implement selection-aware multi-clip Cut/Copy/Paste/Delete with relative clip timing and relative track offsets per accepted Reviews 09–13; paste only to existing compatible destination tracks, reject entire operation if insufficient; no ripple; snap behavior as approved. Cut copies then removes immediately. Paste is a separate undo transaction.
- Support selected-track Delete with confirmation (Review 31). For track Cut/Copy/Paste, **do not silently implement lossy or partial track duplication**: evaluate full track semantics (clips, effects, routing, automation) and the distinction between Duplicate Track and Copy/Paste Track Settings (Reviews 32–33). If unresolved, keep track Cut/Copy/Paste disabled and explicitly report as a scope blocker/decision, rather than invent behavior.
- Add large, permanently visible global **UNDO** and **REDO** beside the four UAT groups on the **same toolbar band**. Preserve menu Undo/Redo and history availability rules. Reduce UAT button widths only as necessary (at most 80% from previous width), retain height, labels, 2×2 group structure, transport and Inspector/Workspace controls. Verify minimum supported window.

## Task C — MOVE
- Fixed MOVE buttons: **UP, DOWN, LEFT, RIGHT**.
- Timeline: move selected clips together by one current grid step left/right, or one existing destination track up/down; preserve relative arrangement and clip types; reject invalid cross-track destinations as one group; maintain snapping, selection and one undo.
- Tracks: UP/DOWN reorders selected tracks **as a contiguous block** (Review 30), preserving their relative order; LEFT/RIGHT disabled. No implicit track creation.
- Use existing drag behavior where applicable without regressing it. Do not invent time shifts for track objects.

## Task D — SIZE
- Fixed SIZE buttons: **START −, START +, END −, END +**.
- Timeline: adjust selected clip playback boundaries by one current grid step per click; preserve source non-destructively and reject invalid ranges/unsupported media or take cases atomically. Define START direction consistently (earlier/later), preserve end unless the action explicitly changes it; clamp/reject according to engine capabilities and report edge semantics in PR.
- Tracks: map SIZE to existing track-height changes using a consistent accessible mapping; do not reinterpret START/END as temporal operations for tracks. **Mapping requires confirmation** before coding if existing approved design does not define which buttons mean height increase/decrease. Keep any unmapped buttons disabled rather than inventing semantics.
- One undoable edit for engine-backed state. UI-only persisted track-height changes should use the existing persistence model; do not claim engine UndoManager support without implementing it.

### Accepted Snap increment clarification (2026-11-20)
- Timeline clip MOVE LEFT/RIGHT and SIZE START −/+, END −/+ buttons: **Snap ON = one selected grid division; Snap OFF = exactly 10 ms (0.010 s) per click**, independent of tempo/grid. This is milliseconds, not seconds. For homogeneous clip selections use the same increment for all selected clips, validate atomically, and create one undo transaction per press. Do not change mouse drag behavior or track UP/DOWN/height step semantics.
- Test at different tempos and grid settings with Snap OFF to verify an exact 0.010-second delta; with Snap ON verify selected-grid step.

## Track clipboard and duplicate mapping — ACCEPTED 2026-11-20

- When **Tracks** is the active UAT target, **CUT is disabled**; there is no Cut Track operation.
- **COPY** copies selected track settings, not clips or automation. **PASTE** applies copied track settings to compatible destination track(s), replacing effects/routing/volume/pan while preserving existing clips and automation; reject incompatible destinations atomically. These semantics follow accepted Reviews 32–33. Where multi-track source-to-destination mapping is not specified, request clarification before implementing rather than guessing.
- **DELETE** removes selected track(s) only after the existing required confirmation (Review 31).
- **Duplicate Track** is a separate Track Inspector action, not UAT COPY/PASTE. It duplicates the complete track including clips, effects, routing, and automation, preserving track color and using the approved “ Copy”, “ Copy 2” name suffixes (Reviews 32, 34–35).
- Preserve selection/focus rules and one undoable transaction per completed action. For v0.22.2, do not silently substitute full duplication for settings copy/paste; flag any unimplemented approved behavior in acceptance notes.
