# Licensing and redistribution

**A freely distributed open-source build is feasible in principle.** The candidate build uses AGPLv3 for JUCE and the combined distribution, and GPLv3 for Tracktion Engine and the covered files in JUCE's bundled VST3 SDK. GPLv3 §13 and AGPLv3 §13 allow combining works under those two versions. Each covered part keeps its applicable licence. The project owner approved AGPLv3 for SimpleDAW’s original code. The grant and upstream notices are recorded in the repository. Binary publication remains subject to the checks below. [GPLv3](https://www.gnu.org/licenses/gpl-3.0.en.html) · [AGPLv3](https://www.gnu.org/licenses/agpl-3.0.en.html)

## Before uploading a downloadable EXE

1. The original SimpleDAW code is now licensed under AGPLv3-only. See [LICENSE](../LICENSE) and [COPYRIGHT](../COPYRIGHT).
2. Audit the linked components for the exact source revision and configuration, including JUCE and Tracktion bundled code and the static MSVC runtime. Confirm the Microsoft toolchain redistribution terms and the GPL/AGPL System Library exception as applicable to the shipped Windows build. Retain applicable copyright, licence, attribution and warranty notices. Publish GPLv3 and AGPLv3 texts and per-component notices with the distribution materials.
3. Make exact Corresponding Source available alongside the binary under an applicable GPLv3 §6 / AGPLv3 §6 method. For an online release, provide equivalent source access at no extra charge and clear directions alongside the binary. Include the SimpleDAW sources, exact covered dependency sources and changes, and scripts needed to build and install the covered executable. Preserve access for the required period. The EXE download can contain only `SimpleDAW.exe` if the accompanying release materials supply the applicable notices and source access without adding files needed at runtime.
4. Start with the default WASAPI-capable build. To publish an ASIO variant, resolve the exact SDK licence and source obligations separately.

Static linking removes app-local DLL deployment for the bundled modules and MSVC runtime. It still incorporates dependency code into the executable, so the combined-work obligations and component notices apply. GitHub Actions can build and test privately on the runner. Exposing an executable as an Actions artifact is a distribution decision governed by the same obligations as a release download. The workflow has no upload step until the outstanding checks and release materials are complete. [Microsoft Visual C++ redistribution](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files)

## Remaining checks on the standard Windows build

- **Static Microsoft runtime.** Microsoft documents that `/MT` incorporates `libcmt.lib`, `libvcruntime.lib`, `libucrt.lib` and the static C++ library `libcpmt.lib`. The earlier PE inspection confirms the binary has no VC redistributable DLL imports. Microsoft's Visual Studio 2022 REDIST list and product terms govern redistribution, and the FSF FAQ addresses dynamic MSVC runtime use. These sources do not establish the product-term grant and GPL/AGPL System Library treatment for the exact static objects incorporated by the hosted Visual Studio build. Confirm the applicable Microsoft grant and conditions and the System Library treatment or use a compatible toolchain with an explicit redistribution grant for static linking. [Microsoft CRT library reference](https://learn.microsoft.com/en-us/cpp/c-runtime-library/crt-library-features) · [Visual Studio 2022 REDIST](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution) · [FSF GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html#WindowsRuntimeAndGPL)
- **Bundled code.** The [notice inventory](../THIRD_PARTY_NOTICES.md) includes the pinned upstream texts reviewed so far. Reconcile file-level notices against the actual linked modules before publication. The enabled SoundTouch build requires a documented LGPL compliance route for static distribution, including applicable notices and a way to rebuild or relink with a modified library. [SoundTouch source notice](https://github.com/Tracktion/tracktion_engine/blob/0a5f4e6a5f53d09c89b414a44386a12df7fa1ec6/modules/tracktion_engine/3rd_party/soundtouch/include/SoundTouch.h)
- **Source alongside the binary.** CI records exact commits. The [source retrieval instructions](corresponding-source.md) describe how to reproduce the inputs and how to pair the binary with a tested source archive when uploads are enabled.
