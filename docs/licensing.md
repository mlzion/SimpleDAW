# Licensing and redistribution

**A freely distributed open-source build is feasible in principle.** The candidate build uses AGPLv3 for JUCE and the combined distribution, and GPLv3 for Tracktion Engine and the covered files in JUCE's bundled VST3 SDK. GPLv3 §13 and AGPLv3 §13 allow combining works under those two versions. Each covered part keeps its applicable licence. The project owner approved AGPLv3 for SimpleDAW’s original code. The grant and upstream notices are recorded in the repository. Binary publication remains subject to the checks below. ## Static Microsoft runtime

Microsoft's CRT reference identifies the Release `/MT` inputs as `libcmt.lib`, `libvcruntime.lib` and the Windows SDK's `libucrt.lib`, plus `libcpmt.lib` for the C++ standard library. Its deployment reference describes embedding library object code in an executable and recommends dynamic deployment for servicing. The VC Runtime section of the Visual Studio 2022 REDIST list allows redistribution of specified unmodified files in `VC\\redist` for licensed users subject to the product terms. It identifies the retail CRT redistributable packages and merge modules. The list does not name those four static library inputs. Standalone startup and an import table without VC redistributable DLLs verify deployment. They do not establish the terms for the embedded code. [Microsoft CRT reference](https://learn.microsoft.com/en-us/cpp/c-runtime-library/crt-library-features) · [Microsoft deployment reference](https://learn.microsoft.com/en-us/cpp/windows/deployment-in-visual-cpp) · [Visual Studio 2022 REDIST list](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution#visual-c-runtime-files) · [Visual Studio 2022 product terms](https://visualstudio.microsoft.com/license-terms/vs2022-ga-proenterprise/)

**Release blocker.** Obtain an applicable Microsoft grant or written confirmation covering redistribution of the exact hosted Visual Studio 2022 and Windows SDK static runtime object code in this EXE. Confirm that its conditions work with the project's AGPLv3/GPLv3 conveyance terms, including the licence's System Library treatment. The FSF's example covers dynamic use of the Microsoft runtime. It does not resolve this static configuration. If the grant or compatibility cannot be confirmed, the owner can authorize qualifying a Windows toolchain with a compatible static runtime and rerunning the archive and single-EXE tests. That decision does not require an audio-engine change. [FSF GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html#WindowsRuntimeAndGPL) · [AGPLv3 §1 and §12](https://www.gnu.org/licenses/agpl-3.0.en.html)

## SoundTouch

The pinned SoundTouch files grant LGPL 2.1 or later. The intended distribution path uses LGPL 2.1 §6(a), which permits providing the complete machine-readable application in source form with library source and build scripts so recipients can build the executable with a modified library. Include the library notice and licence, preserve the recipient's ability to modify the work for their own use and reverse-engineer it to debug those modifications, and publish the matching source at equivalent access under §6's download provision. The single-file EXE can stay statically linked. The [archive instructions](corresponding-source.md) give the replacement path and build commands. No licence incompatibility was identified for SoundTouch under this route. The Microsoft runtime review still applies to the executable as a whole. [Pinned SoundTouch header](https://github.com/Tracktion/tracktion_engine/blob/0a5f4e6a5f53d09c89b414a44386a12df7fa1ec6/modules/tracktion_engine/3rd_party/soundtouch/include/SoundTouch.h) · [LGPL 2.1 §6](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.en.html#section6)
