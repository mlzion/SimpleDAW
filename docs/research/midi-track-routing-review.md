# MIDI track routing code inspection

Static review, 22 November 2026. The [Master Specification amendment](../specifications/midi-track-routing.md) defines the target behavior. This review covers main at `5b1975f`, Inspector at `1f69850`, Piano Roll P0 at `6486a5f` and the dependencies pinned in CMake. Live Windows controller tests and Windows CI were outside this review.

## Inspector

- Track Inspector already separates **Input** and **Record Arm**. Its picker enables all known physical inputs before listing them and assigns one target with automatic monitoring. It lacks track input and output channel controls. The MIDI Clip Inspector exposes velocity and transpose without a channel control. [Input assignment](https://github.com/mlzion/SimpleDAW/blob/1f698503b7746d8c16aa0322659ff74f1c08b435/src/MainGui.inc#L4416) · [Clip controls](https://github.com/mlzion/SimpleDAW/blob/1f698503b7746d8c16aa0322659ff74f1c08b435/src/MainGui.inc#L496)
- The temporary importer accepts one note-bearing file track even if it contains several channels. It copies note pitch, timing, duration and velocity into one sequence and drops the note channels and non-note messages. It rejects a second note-bearing file track. This is a compatibility conflict even for some single-track files. [Importer](https://github.com/mlzion/SimpleDAW/blob/1f698503b7746d8c16aa0322659ff74f1c08b435/src/Main.cpp#L556)

## Piano Roll P0

- The editor has no channel control. Its audition code reads `clip->getMidiChannel()` despite the branch documentation identifying the track as the routing context. The P0 regression sets Channel 5 on the clip and expects it on audition messages. Resolve the channel from the track and keep the captured channel for note-off. Update the branch regression to set Channel 5 on the track. [P0 documentation](https://github.com/mlzion/SimpleDAW/blob/6486a5fefa42a4d6ebe3b10455b1c31b4c532d28/docs/research/piano-roll-p0.md) · [Audition](https://github.com/mlzion/SimpleDAW/blob/6486a5fefa42a4d6ebe3b10455b1c31b4c532d28/src/PianoRoll.h#L548) · [Regression](https://github.com/mlzion/SimpleDAW/blob/6486a5fefa42a4d6ebe3b10455b1c31b4c532d28/src/PianoRollTest.inc#L70)

## Setup and USB discovery

- **Options → Audio and MIDI Devices** constructs a JUCE selector with MIDI inputs visible and outputs hidden. JUCE enumerates on construction. On Windows the WinRT backend uses input endpoint watchers where available, with WinMM fallback querying the OS input device list. A USB controller should appear when Windows exposes it as a MIDI input. Enumeration alone does not establish that the device opens or delivers MIDI. [SimpleDAW Setup](https://github.com/mlzion/SimpleDAW/blob/5b1975fc2324572142b93b3a2a8f87e2a52880bc/src/Main.cpp#L249) · [JUCE Windows backend](https://github.com/juce-framework/JUCE/blob/19edd538429c93d277bf95b55aaa7e3eb545f951/modules/juce_audio_devices/native/juce_Midi_windows.cpp)
- Reopening Setup enumerates again without restarting the app. While open, the selector refreshes on AudioDeviceManager change messages, which the manager sends on MIDI device notifications. Tracktion separately refreshes the inventory used by Arm and the Inspector. Its default polling interval is four seconds. A MIDI input or output scan exceeding 200 ms disables polling, and the JUCE manager change callback in Tracktion rescans audio inputs/outputs only. Setup can therefore show a device that the track picker cannot yet select. [JUCE selector](https://github.com/juce-framework/JUCE/blob/19edd538429c93d277bf95b55aaa7e3eb545f951/modules/juce_audio_utils/gui/juce_AudioDeviceSelectorComponent.cpp) · [JUCE manager](https://github.com/juce-framework/JUCE/blob/19edd538429c93d277bf95b55aaa7e3eb545f951/modules/juce_audio_devices/audio_io/juce_AudioDeviceManager.h#L517) · [Tracktion inventory](https://github.com/Tracktion/tracktion_engine/blob/0a5f4e6a5f53d09c89b414a44386a12df7fa1ec6/modules/tracktion_engine/playback/tracktion_DeviceManager.cpp#L497)

## Smallest implementation change

Reuse the existing input picker, Arm and Monitor paths. Add persisted input/output channels to the track, filter live input per destination track and remap channel messages before the existing instrument. Have Piano Roll audition read the same track setting. Keep Tracktion's serialized clip channel readable for legacy migration. Guard the current importer against lossy files until channel separation and event preservation can land together.

For device refresh, reuse the JUCE Setup list. Request Tracktion's existing asynchronous `rescanMidiDeviceList()` when Setup closes while stopped, and rebuild track input choices after the rescan finishes. This gives a restart-free manual refresh path even if automatic polling stopped. Verify on Windows with a controller connected before startup and one connected while Setup is open, including an unplug/reconnect and successful input on an armed track.
