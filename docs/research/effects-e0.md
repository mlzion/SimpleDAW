# SimpleDAW Effects Research — Phase E0

**RECOMMENDED.** Use Tracktion's ordered track plugin list as the effects chain. Reuse native effects where their controls match the product requirements. For E1, keep Tracktion's native Reverb only if the owner approves a revised control and preset scope. The approved scope calls for independent Decay and a credible Plate, which require a different reverb backend or additional DSP. Plexi is a feasible native port candidate once source reuse is authorized and the reference sound is captured.

## Baseline and design

**VERIFIED.** Reviewed main at `02a10e144acddc8cb0d5071aeeb2f551de71ab2c` (merged [PR #14](https://github.com/mlzion/SimpleDAW/pull/14)), the [Master Scope](../specifications/SimpleDAW_Master_Spec_With_Pending.pdf) §§2–4 and 8–10, [accepted UAT decisions](../specifications/v0.22-design-decisions-reviews-01-82.md), [effects supplement](../specifications/effects-and-instruments-supplement-2026-11-21.md) and [architecture](../architecture.md). v0.22.2 is separate in open [PR #10](https://github.com/mlzion/SimpleDAW/pull/10), head `ccd1210` at review time.

**VERIFIED — implemented on main.** One JUCE application owns a Tracktion Engine and active Edit. Both track commands create Tracktion audio tracks; MIDI or audio clips use the same graph. Tracktion handles devices, transport, plugin processing, export and Edit serialization. `insertBuiltIn` creates a plugin through the Edit's PluginCache and inserts it at index 0. Insert → Add Reverb, a built-in synth and VST3 loading already exist. The collapsible Inspector surface and read-only bottom Effects chain can take focus. There is no parameter editor or Inspector effect management. The smoke test saves an Edit with native reverb, finds its type after reopen and checks an audible stereo offline export. That test does not isolate wet output or verify settings, bypass or tails. See [Main.cpp](../../src/Main.cpp) (`insertBuiltIn`, smoke test, project save/load) and [MainGui.inc](../../src/MainGui.inc) (`selectedEffects`, Insert handler and workspace layout).

**VERIFIED — accepted design, pending implementation.** Inspector owns track effect management, individual and track-wide bypass, and reorder by drag/drop or Up/Down. The shared bottom slide-up editor displays selected effect controls with large controls and numeric values, following Editing Windows > Inspector > Timeline > Tracks. Preserve other editor state and existing selected-object rules. The current resizable workspace is a foundation; the Master Scope specifies fixed height for the approved slide-up editor. Keep existing external VST3 behavior and missing-plugin placeholders distinct from the built-in editor workflow. Effects run after instrument output, in displayed order, with eight slots, independent instances and at most one guitar or bass amp per track. Instruments and two track LFOs are outside the slot count. De-esser is excluded.

**PENDING — specification reconciliation.** The supplement references whole-track duplication, while the v0.22.2 UAT amendment replaces the earlier Inspector Duplicate Track proposal with Tracks-area COPY/PASTE. Preserve full duplication through the approved UAT route and Inspector's selective COPY SETTINGS/APPLY SETTINGS. Seek confirmation of the wording before touching either workflow. The amendment transfers volume, pan, chain/values and output routing; it excludes input/arm/monitoring, mute/solo, identity, clips and automation, and rejects the whole apply if destination effect automation would be invalidated.

## E1 Reverb

| Requirement | Finding and recommendation |
| --- | --- |
| Room Size | **VERIFIED** native 0–1, default 0.3. JUCE maps it to comb feedback `0.7 + 0.28 × roomSize`; delay lengths are fixed for a given sample rate. It changes the perceived space and decay together. The engine's value formatter produces 1–11; use an explicit, documented normalized display if the native scope is approved. |
| Decay | **BLOCKED** on this backend. No independent RT60/time or normalized decay parameter. Relabeling or adding a second control over the same feedback coefficient does not satisfy independent adjustment. |
| Damping | **VERIFIED** native 0–1, default 0.5, mapped to 0–0.4 in the feedback filter. |
| Wet/Dry | **RECOMMENDED** show wet percent, with dry complement and unity endpoints. For a new stock instance with width locked to 1 and Freeze off, a linear mix `m` maps to native wet `m/3` and dry `(1−m)/2`, accounting for JUCE gain multipliers. Verify endpoints against dry and wet reference renders. Existing projects may contain independent wet/dry, width and freeze values; preserve them and define explicit migration or a legacy editor before applying a single-slider mapping. |
| Small Room, Large Room, Hall | **RECOMMENDED** use distinct, audibly verified snapshots. Native snapshots vary feedback, damping, mix and width with a fixed topology. Label presets after impulse/tail measurements and listening. Exact settings remain pending. |
| Plate | **BLOCKED** for a defensible plate mode on current core Reverb. Source has one fixed comb/all-pass topology plus Freeze. An optional Airwindows reverb name is insufficient evidence of independent size and decay or a suitable plate. |
| Adjust during playback | **VERIFIED** Tracktion reads automatable values by render block and JUCE smooths feedback, damping and gains (10 ms). Fixed-size structures are prepared at sample-rate initialization. **PENDING** live drag/preset transition, first-reflection, quiet-tail and CPU checks. The wrapper uses an amplitude-based silence shortcut that merits impulse/tail verification. |
| Bypass and persistence | **VERIFIED** `Plugin::setEnabled` writes an undo-managed `enabled` property; the PluginNode checks enablement. Native parameters attach to cached Edit state and restore from ValueTree. **PENDING** verify dry equivalence, tail behavior, bypass reversal and save/reload of actual values, order and preset provenance. |

Sources: `plugins/effects/tracktion_Reverb.{h,cpp}`, `plugins/tracktion_Plugin.cpp`, `playback/graph/tracktion_PluginNode.cpp` in the pinned engine, and pinned [JUCE Reverb](https://github.com/juce-framework/JUCE/blob/19edd538429c93d277bf95b55aaa7e3eb545f951/modules/juce_audio_basics/utilities/juce_Reverb.h).

**RECOMMENDED** if all approved E1 controls and sounds remain required: qualify a compatible algorithmic reverb with separately tunable delay geometry/diffusion and feedback (decay), damping, and a plate topology or materially distinct plate response. Use the same Tracktion insert contract as native effects. Prefer an existing license-compatible implementation after source and listening review. If necessary, price original DSP work as a separate dependency before E1 integration. Measure broadband and frequency-dependent decay and validate live smoothing before publishing units or presets. Fixed IR snapshots alone do not provide independent continuous Room Size and Decay. **PENDING** owner approval for that backend search or for a revised E1 pilot using stock reverb with its real controls and Plate deferred.

## Plexi native C++ port

**VERIFIED.** The original [Bostone repository](https://github.com/mlzion/Bostone-/tree/d82147ea013af3789eb980c9be60e3a2954375db) was accessible at `d82147ea013af3789eb980c9be60e3a2954375db`. Review targets were `plugins/Plexi/jsfx/Bostone_Plexi_v0.3.jsfx` and `Bostone_Plexi_v0.4.jsfx`, `plugins/Plexi/docs/plexi-v0.3-dsp.md`, `plexi-v0.4-technical.md`, `plexi-v0.4-cabinet.md`, companion tests, `plugins/Preamp/README.md` and `shared/source-register.md`. No cabinet WAV is bundled. REAPER is the reference host, with no need to ship REAPER or execute EEL2 in a C++ port.

- **VERIFIED — amp path.** v0.4 carries forward the stereo v0.3 amp. Input trim, frequency shaping and biased nonlinear preamp feed an interactive passive nodal tone stack, then differential power-stage saturation with presence/tightness and output conditioning. Preserve stereo history, the solver coefficients and state updates, smoothing, DC behavior, gain and ceiling. The separate Bostone Preamp v0.2.1 is an optional upstream EQ/cascaded soft clipper. Including it changes the baseline.
- **VERIFIED — amp controls.** Sliders 1–10 are Amp Enable (on), Input Gain −24…+24 dB (0), Preamp Drive 0…36 dB (6), Bass/Middle/Treble 0…10 (5 each), Presence 0…10 (4), Power Drive 0…24 dB (3), Bass Tightness 0…10 (5), Output −36…0 dB (−12). Source steps are 0.1 dB and 0.01 for the 0–10 knobs. v0.4 adds cabinet enable (on), IR Level −36…+12 dB (0), 4 processing modes (Raw default, Apply −18 dB, linked peak normalize 0 or −18 dBFS), separate wet and dry −120…+6 dB (0 and mute), HP 0…2000 Hz, LP 0…20000 Hz (both off), length 0…500 ms (0 means full, capacity applies) and filename selection. Whole-effect bypass, amp-only bypass and cabinet bypass are distinct.
- **VERIFIED — cabinet.** v0.4 uses uniform 64-sample FFT overlap-add, a bounded 4096 processed-frame IR, mono dual-mono or independent stereo convolution and reported 64-sample latency (1.33 ms at 48 kHz, plus device/graph latency and any IR leading silence). Cabinet bypass returns aligned amp output. v0.4 searches REAPER's Data/BostoneIR and serializes the filename. Mono/stereo WAV at 44.1/48 kHz, resampling with FIR-area compensation, explicit front crop, linked normalization, preserved leading silence and aligned amp-only fallback define the reference behavior. Source uses REAPER media I/O and packed real FFT/`convolve_c`; those are host dependencies of the JSFX. Loading during stopped transport can still stall monitoring in the reference.
- **RECOMMENDED — port amp first, then cabinet.** Translate the original math and processing order, preserving precision and parameter semantics; establish v0.3 parity before adding v0.4 latency and cabinet. Evaluate the pinned [JUCE DSP convolution](https://github.com/juce-framework/JUCE/blob/19edd538429c93d277bf95b55aaa7e3eb545f951/modules/juce_dsp/frequency/juce_Convolution.h) or an equivalent bounded native convolution. Compare against direct FIR and v0.4 reference before selection. Match preprocessing explicitly; JUCE convolution options, partition scheduling, resampling, trimming, normalization and latency must be qualified. Decode and prepare impulses off the audio thread, preallocate, and publish prepared state at a safe boundary. Keep dry alignment and report actual latency to Tracktion. For v0.4 compatibility, preserve its 64-sample alignment or document a measured difference. Compare fixed and changing control settings at several rates, including worst-case blocks and channel counts. Preserve existing no-custom-oversampling behavior for parity; evaluate any future oversampling separately for aliasing, latency and CPU.
- **RECOMMENDED — presets and project files.** Keep stable native IDs mapped to the JSFX slider indices, preserve units/defaults and include amp model and cabinet asset identity in versioned state. Transfer settings by explicit manifests first; REAPER preset/project import is a separate scope decision. Identify an IR by a project-relative or managed asset reference plus fingerprint, never menu index alone. Missing assets should reopen with a visible status, relink and aligned amp-only operation. Choose project copy versus external reference and crop/cap policy with the owner.
- **PENDING — sound and reuse.** Source fidelity is feasible, but perceptual equivalence and CPU headroom require measurements. Obtain a versioned REAPER project or settings manifests, dry DI and wet renders with and without cabinet, REAPER version, sample rates/block sizes, oversampling settings, exact WAVs and rights for sharing fixtures. Use reference renders and level-matched listening; exact float equality across engines is unnecessary. Reuse cabinet handling, stereo filter and coefficient primitives, state and preset infrastructure across amp models. Qualify each new guitar or bass preamp/power voicing, tone stack, cabinet and bass headroom independently.
- **BLOCKED — source/asset redistribution.** Bostone's register records original production DSP and no project-wide redistribution license. Obtain an explicit compatible grant from the rights holder for porting, tests and corresponding-source distribution. The reference citations do not grant rights to third-party code or audio. Establish rights separately for bundled IRs, test DIs and renders. User-provided files can remain external; no licensed cabinet library was identified or assumed. Review model names/marks before distribution.

**VERIFIED — E0 check.** Ran `python3 run_tests.py --plugin Plexi` on Linux at the Bostone commit above. All 22 Plexi numerical/source tests and 5 shared source compatibility tests passed. Bostone documents prior Windows REAPER cabinet-switching confirmation. E0 ran no REAPER host, native port, SimpleDAW build, Windows live tests, benchmark or Windows CI.

## Internal architecture

**RECOMMENDED.** Compile custom DSP into the application through a small Tracktion plugin adapter with a registered stable type. The existing engine instance and graph own processing. Reuse PluginManager/PluginCache creation, PluginList ordering, ValueTree/project serialization, undo and graph latency reporting. Start with an effect catalog and a compact descriptor per type giving stable parameter IDs, label, unit, domain, step, default, display mapping, and automation/modulation eligibility. Use native `AutomatableParameter` interfaces where available. Keep custom DSP in ordinary C++ processing units with prepare/reset/process and a latency query where needed. An independent test target can link the same code. There is no requirement for separate runtime DLLs or a new plugin ABI. See pinned `plugins/tracktion_{Plugin,PluginList,PluginManager}.{h,cpp}` and `playback/graph/tracktion_PluginNode.cpp`.

**RECOMMENDED.** Treat the engine list as authoritative; identify user inserts separately from instrument, meter, volume/pan and routing nodes. Insert after instrument output and preserve the existing fader/routing relationship when translating visible effect positions to engine positions. Count user audio effects toward eight, including hosted audio effects subject to the approved chain policy. Validate additions, paste and chain transfers before mutation. Preserve loaded legacy chains, including projects above any new limit, until an explicit compatibility policy is approved. Key selections, preset state and future automation by track/effect identity plus stable parameter ID; reordering preserves identity. Paste creates fresh identity and DSP history. Use one undo transaction for compound changes. Keep unsupported hosted effects and their state in order with a placeholder.

**RECOMMENDED.** Persist parameter values and instance enable state in plugin state. Factory presets are versioned snapshots with stable IDs; save current values plus preset provenance for edited presets. Effect paste includes type, model, settings, preset modifications and bypass. Track-wide bypass should preserve the individual intent and preserve instrument and routing behavior. Investigate representing the effective enabled state through Tracktion while retaining separate per-instance intent. Verify latency continuity and graph rebuild semantics for enabled, bypassed, reordered and removed effects. Keep UI listeners scoped to the current Edit/selection so undo, track change and project close cannot leave stale targets.

**RECOMMENDED.** v0.23 supplies selected track and Inspector focus; E1 uses it to open the shared editor through the existing workspace and UAT dispatcher. Bind generic large sliders/readouts to descriptors and plugin instances. Route add, select, bypass and remove through the Inspector. Use existing project dirty state and undo, and preserve editor choice/focus semantics. Defer eight-slot UX, reorder and chain clipboard delivery beyond the E1 proof unless separately approved.

**RECOMMENDED.** Reserve parameter addressing for the Master Scope's future automation lanes and the supplement's two independent per-track LFOs. Modulate the effective playback value without destructive writes to the stored base value or automation curve. Keep natural-unit bounds and smoothing, and accept destinations by capability. Inspect Tracktion's automatable-parameter/modifier pipeline before choosing integration. LFO arithmetic, phase/reset, rate limits, safety/clamping and touch/write interaction remain **PENDING**. Keep file I/O, memory allocation and graph mutations out of the real-time DSP path.
